## 1. Package collection start time (PR #65)

Setting the collection time **already worked at booking** but was invisible
afterwards and undocumented.

- `POST /packages/request`: `isImmediate: true` = ASAP (server slots ~20 min
  out), or `isImmediate: false` + `pickupDate` — **≥ 30 min ahead**, on the
  **15-minute grid** (`:00/:15/:30/:45`), **≤ 30 days out**.
- **New:** `GET /packages/{id}/status` now returns `pickupDate` +
  `isImmediate`, so the PENDING screen can show "collection starts at …"
  with a countdown.
- Matching starts at **T-30 before the slot** — a far-future booking sitting
  in `PENDING` is the design, not a stall.
- Documented in `docs/PACKAGES_API.md` §1.1.

**Mobile action:** render the pickup slot on the package screen; build the
time picker with the three constraints above.

## 2. Package ratings guide (PR #66)

`docs/PACKAGE_RATINGS_API.md` — standalone reference for the package-rating
flows only, using real captured responses:

- Sender → driver: `POST /packages/{id}/rate`, read-back
  `GET /packages/{id}/rating`, and the `rate_your_trip` nudge whose payload
  carries `packageId` (route to the **package** rate sheet).
- Driver → sender: ratables now return `kind: "passenger" | "sender"`;
  senders are rated via `POST /drivers/trips/{tripId}/rate-package`.
- Shared rules: 5 levels, `bad` requires a message, one rating per package
  per side (409 on repeat), same ★ aggregates as trips.

**Mobile action:** wire both rate sheets per the guide; no backend changes
in this PR (the feature itself shipped earlier as #60).

## 3. Dynamic platform currency (PR #67)

The site currency is now a runtime setting switchable from the admin
portal between **Jordanian Dinar** and **Syrian Pound**.

- **Public, no auth:** `GET /platform/currency` →
  `{ code, symbolEn, symbolAr, nameEn, nameAr, decimals }`
  (JOD → `JD / د.أ / 2 decimals`; SYP → `SYP / ل.س / 0 decimals`).
- **Portal:** Wallet settings → "Platform currency" card (bilingual radio
  options). Super admin saves; other roles read-only. Every money label
  across the portal (40 spots, 17 pages) now follows the selection.
- **Display-level only:** amounts are stored as plain numbers and are
  **not converted** — everything is simply shown in the active currency.
- Verified live: switched JOD → SYP → JOD; the public endpoint reflected
  each change immediately.

**Mobile action:** fetch `/platform/currency` at app startup and format
every amount with the returned symbol + decimals (SYP = whole pounds).
Stop hardcoding "JD".

## 4. Data-only driver pushes (PR #68)

Fixes the bug the mobile team confirmed on a physical Android 15 device:
`offer_received` carried a `notification` block, so a backgrounded app got
an OS-rendered notification and `onMessageReceived` never ran — no
full-screen offer overlay, no ringtone, no countdown.

- Now sent **data-only** (title/body inside `data`, no top-level
  `notification` key): `offer_received`, `offer_no_longer_available`
  (added so a backgrounded overlay can be dismissed when the offer is
  taken), `trip_assigned`, `trip_reminder`, `trip_updated`,
  `passenger_cancelled`.
- Delivery hints included: `android.priority: "high"` and APNs
  `content-available: 1` background headers.
- Informational types (`system_announcement`, `earnings_recorded`,
  `outstanding_balance`, `wallet_low_balance`), all passenger pushes, and
  topic broadcasts are **unchanged** — they keep the `notification` block.

**Mobile action:** none (the app already falls back to
`data.title`/`data.body`). Run the verification: background the driver
app → trigger an offer → device log must show the FCM handler running and
the overlay appearing; repeat with the app killed.
